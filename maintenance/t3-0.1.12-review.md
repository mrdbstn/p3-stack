# Stable T3 0.1.12 compatibility review

Reviewed November 25, 2026, against published stable v0.1.12, commit `ca81b7b97a1c4b91e5ac25768d0f6629f37732fd`, compared with v0.1.11 `59651c1761f6c63e9b6056839067066968e6a406`. [Release notes](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12) cover multi-repository projects, structured outputs, provider reliability, PR watch/read changes, and beta Workflows/connections. A stable release can contain optional beta features; this does not make them mandatory port mechanics.

Review of this broad file is scoped to those types, not an audit of every orchestration event. The maintenance recorder and validator now require seven source hashes together.

Preserve 59 skills, 22 playbooks, 575 imported files, all 24 exact principles and their policy metadata, and the explicit invocation policy. Only the three PR playbooks receive new harness adaptations.

## Semantic review

| Stable change | Port behavior |
|---|---|
| PR read replaces `sections` with `include` (body/checks/threads/comments/diff), flattens state/base/headSha, and always returns counts. Detailed checks use `checkRuns`; threads default unresolved. | Update active PR instructions. Select the exposed schema on older peers. Page conversation/diff, request resolved history when needed, and report incomplete checks, lower-bound unresolved counts, moreComments and log truncation rather than asserting a complete audit. |
| Approval now requires `expectedHeadSha`; merge still requires a current-head pin. | Use the reviewed non-null top-level headSha for approval/merge. Read/review again after drift. Keep proof, CI, operator gates and bottom-up per-PR landing; auto/stack does not waive them. |
| Native creation pushes the thread branch, creates or returns an existing PR, and links the caller. Optional private PRs are host-dependent and fail unsupported hosts. | Commit/review within authorization before creation. A parent still links a child's returned PR. Never silently publish a branch after a private request fails. CLI remains the fallback when native tools are absent. |
| Watch registration returns an already merged/closed state with no watch, or warns when checks already pass and no checks-passed wake is due. | Inspect the response before parking. Confirm terminal state and finish that path, or assess passing checks immediately. Later changes still wake an active watch. Keep parent ownership and `until: "merged"` for owned landing; do not re-arm or poll. |
| Multi-repository projects add `workspaceStrategy.repositories` selection; omission means all tracked Git folders, or none above eight. | Inspect each repository's checkout/branch and required inputs. A primary worktree path does not prove project-wide isolation. Delegation does not expose that selector, so serialize or report a gap when the available API cannot isolate all writable repositories. No unsupported fields or top-level substitutes. |
| A Git delegate bases its primary worktree on the parent's local commit/branch; other repositories match branch names. Plain project folders have no primary commit. | Qualify the old single-repository assumption, keep committed inputs and exclusive branches, and verify actual bases. Do not copy uncommitted input or accept a shared checkout as isolated. |
| Sends/authorized launches accept outputSchema; `t3_submit_output` validates JSON text for the caller's own run; wait can return output and accept untilOutput. | Keep this optional. Launch needs message. Missing output/timeout is not success/cancellation; submit corrected JSON after rejection. Do not invent outputSchema on delegate_task, poll a running child, or treat structured data as new authority. |
| Secret cards add one to eight named fields, with a private file per field. Fields cannot combine with pasted value or secretRef delivery. | One value per input, unique valid names, secret masking for sensitive fields, file-map consumption only inside the needing command. Older peers use separate cards. Never put secrets in reports, briefs, outputs or logs. |
| Background-wait availability is capability-based; waiting:false clears a wait without stopping its tasks. | Mark only already-started background tasks when exposed. No persistent dev servers/watchers and no replacement for delegated completion delivery. |
| Scheduled storage preserves binding on omitted/null thread IDs and adds explicit unbindThread; environment unlink reports endedThere. | These are not new schedule_task MCP fields or permission to unbind/reset a coordinator or disconnect the running environment. Preserve context, binding and existing audit conditions. |
| Workflows/connections ship beta; workflow MCP is hidden from thread agents and driven by outside clients/CLI. Launch adds forwarded workflow provenance. | Optional integrations only. Do not migrate the coordinator, restore retired Orchestrate/plan-checker machinery, forge workflowRun/delegatedFrom, or signal away a human approval. External event streams do not permit running-delegate polling. |

## Additional implementation evidence and limits

Read at the same immutable release commit (paths under `apps/server/src/` unless shown otherwise): `mcp/toolkits/pullRequests/handlers.ts` (read/count/cursor handling, create/link and mandatory approval head pin), `pullRequest/PullRequestWatchService.ts` (already-ended/initial-check responses), `mcp/McpInvocationContext.ts` (background-wait and outside/thread discovery), `mcp/OrchestratorMcpService.ts` (delegated workspace preparation, secret validation and typed send/wait plumbing), `mcp/toolkits/workflow/tools.ts` (outside-only workflow driver), `mcp/toolkits/worktree/tools.ts`, and `packages/contracts/src/worktreeMcp.ts`, `project.ts`, `orchestrationProject.ts` (tracked folders and worktree operations). Worktree handoff acts on the current thread, ends its live session, and is not a child-spawn substitute.

The available client exposes no live T3 model catalog, delegate, native PR/CI or watch tools. Live provider selection, multi-repository delegation, structured outputs, private cards, native forge operations and watch wakes were unavailable and unrun. Source/schema review and repository/WSL/TLC checks are not live model evaluation. The running T3 installation, provider settings and user model configuration remain untouched. Verification results belong in the PR; these hashes establish reviewed source identity only.
