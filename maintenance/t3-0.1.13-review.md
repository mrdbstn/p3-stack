## Semantics and port behavior

| Stable implementation | Required adaptation |
|---|---|
| Native PR creation evaluates project-command permission using effective runtime, interaction mode, link fencing and managed policy. Otherwise it asks the person before running repository push hooks; approval is tied to hook contents, and changing hooks can require another approval. Declined/unconfirmed replies push nothing. | Respect the native outcome and existing authority. Do not retry through CLI/hook-disable flags or manufacture approval. Full access is not a grant beyond the user's authorization or managed policy. No internal digest/approval input is added to the MCP call. |
| A client without approval elicitation can still create/push with hooks off, returning optional `note`. | Read/report the skipped-hook note. Creation success does not establish hook execution. Preserve required repository checks and explicitly report any remaining proof gap. No new universal approval ceremony is added to ordinary authorized work. |
| Agent-mode options can bypass provider approvals, so delegation/thread configuration refuses a new selection below Full access even if advertised. Repeating the same held value grants nothing new; accepted-command retries replay the original receipt. | Distinguish advertised model/effort choices from provider session-mode permissions. Leave refused mode picks out and report the limit; do not raise permissions or switch clients to evade it. Keep exact catalog IDs, role budgets, inherited targets and model-diversity evidence. |
| Optional workflow list adds subject filtering; the outside-only tool remains hidden from thread agents. Workflow pools/subjects and newer internal queue/Stop bookkeeping do not change delegate inputs. | Keep these optional; no coordinator migration, top-level substitute, new polling, invented internal fields, or restoration of retired Orchestrate/plan-checker behavior. Preserve user stop/approval gates. |
| Thread output rejection uses a shared formatter; read/write access wrappers and provider.ts are unchanged. | Keep typed-output correction/resubmission and existing capability limits. No new live-provider or successful-execution claim follows from schema compatibility. |
