# Stable T3 0.1.11 compatibility review

Reviewed November 20, 2026, against published stable v0.1.11, commit `59651c1761f6c63e9b6056839067066968e6a406`, compared with v0.1.10 `7d32075e3757ded707914e2450c3e392a9665765`. Release notes cover native forge/CI tools, merge wakeups, launch fixes, provider/delegation reliability, browser tunnels and port forwarding. UI availability is not proof of an MCP tool or permission to change the running installation.

## Semantics and adaptations

| Stable change | Required behavior |
|---|---|
| PR read/list/create/update/respond/review/merge and CI logs/reruns use the current thread's forge. | Prefer exposed native tools; keep CLI fallback for unavailable operations/clients. Honor forge/environment/write capabilities. Creation uses the pushed caller branch and links the caller; the parent still links child-created PRs. No new merge or communications authority. |
| Read sections and repository lists page with cursors. Conversation threads and logs can remain partial. | Follow nextCursor for the needed sections. Treat truncated/moreComments/log limits as explicit gaps, not complete audit evidence. Repository inventory and thread-linked inventory are distinct. |
| Native merge requires expectedHeadSha; auto can wait for later pushes, and stack covers lower layers. | Pin the reviewed current head, keep per-PR proof and bottom-up landing, avoid stack bypass, and read back confirmed merged state plus intended base. Auto/queue success is not a merge. |
| Respond can post a reply before resolution fails. Rerun refreshes a watch's pending-check bookkeeping. | Retry failed resolution without body; do not blindly repeat non-idempotent replies/reviews/reruns/merges. Do not re-arm an active watch after a rerun. |
| Watch reactor emits merge/closure completion news, then clears the watch. Agent-initiated immediate completion can suppress its redundant wake. | Use native wakeups for asynchronous/external completion; read immediate operation results. Confirm live state before advancing. Recovery schedules remain conditional for older linked peers or an actual durable audit, rather than mandatory duplicate merge polling. |
| Watch input adds `until`, defaulting new watches to checks and preserving an existing value when omitted. This controls working status, not watch removal. | Owned shipping passes `until: "merged"`; user handoff uses checks. Do not confuse completed checks with stopped monitoring or omit the field on a supported owned-merge path. Older linked peers can require an explicit reported fallback. |
| Outside callers' omitted launch workspace follows project settings; omitted origin behavior follows new-worktree settings. Existing explicit branches are rejected. | Pass strategy/base/origin explicitly for authorized top-level work. Use the same clientRequestId after a lost reply. Do not replace internal delegates with ordinary conversations. |
